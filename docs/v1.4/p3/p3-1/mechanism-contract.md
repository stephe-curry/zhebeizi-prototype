# P3-1 正式机制合同

## 一页人生怎样留下梦想

每槽仍只有一个主场景和一条正式事实。玩家完成真实接触后，下一槽的「我的手记」会列出新候选及首次接触年龄、场景。合上手记就可以继续普通人生。候选和已确立梦想分开查询。

| 从哪里读 | 读到什么 |
| --- | --- |
| LifeContinuity.candidates(run) | 路线、目标、窗口与已提交接触的来源 |
| LifeContinuity.dreams(run) | 每个目标的首次确立年龄、确立来源、当前状态、历次变更、投入及阶段结果引用 |
| LifeContinuity.qualifications(run,id) | 此路线实际取得的资格动作及来源 |
| LifeRoutes.history(run,id,kind) | 属于该路线的动作及所在事实的引用，可以按动作种类筛选 |
| LifeRoutes.contract(run) | 仍与当前岗位匹配的聘约收据 |
| LifeContinuity.employment(run) | 当前聘约的排班方式，未选择新聘约时为空 |

确立、搁置、重新拾起和放下均先进入草稿。撤回只清除当前意向。确立与重拾会重查窗口和路线条件。一个目标的操作只改变该目标。放下后允许在合法窗口重新拾起。最终目标由路线明确指定的检验结果确认。回忆录逐项展示玩家真正记下的目标和投入次数。

## 结算与来源

页面向 E.chooseDream 传入路线与操作 ID，专属操作的具体方法由 LifeRoutes.chooseMethod 选择。费用与结果来自注册定义。E.preview 合并主事、支援、余段、短回响、路线和现有聘约。涉及现金支出时，在状态副本上试算整槽，把当期工资剔除后再检查余额。E.canApply 与 E.commit 使用相同的条件；最终由 E.commit 写入当前人生。每槽至多选一项手记安排。

事实 actions[0] 记录 schema、actionId、kind、routeIds、sourceRefs、payload、costs 和 result。宿主事实提供年龄、分支、时段、事件和主选择。已有来源有分支号就保留，没有的沿用 null。多路线可引用同一收据。投影仅遍历事实，不会再次付费、发薪或生成物件。

## 聘约、机会与检验

办公室沿用 career 表示职业身份。聘约决定该期间的出勤与工资。改签半班时会在当期额外占用一段办妥交接。后续各期，半班占主安排中的一段，整班占满两段。停薪学习和离岗的岗位工资为零。实际可支配时间还要扣除生活主事。

手记动作由可见性观察记录 seen。已曝光的可延后动作标记 deferred，到真正再次选择时才写 continuedFrom。当届测评结束即到期。窗口中途失去条件，仍在当前曝光记录里的动作标记 invalidated。没有打开或选择手记的整页可不附 routeOffers，历史读者应当保留未知状态。

检验读取路线定义的硬性资格、准备来源和届次函数，外因按种子、路线、规则版本和届次计算。玩家确认参与才有结算收据。后续机会仍按自己的窗口和费用处理。两条正式梦想目前都没有新增最高荣誉判定。
