## 2. 唯一事实协议

在现有每槽唯一fact内增加可选 `actions`（命名可按现有风格），每条至少含：

```js
{
  actionId: 'dream-03-establish', // 声明ID；输入不能自行提供费用或结果
  kind: 'dream-established', routeIds: ['03'],
  sourceRefs: [{branch:'walk',slot:7,eventId:'life-7',choiceId:'life-7-0'}],
  payload: {target:'undergraduate', ruleVersion:'p3-v1'},
  costs: {time:0,energy:0,money:0}, // 确立本身不记训练；实操成本另算
  result: {state:'active'}
}
```

`dream-established / dream-paused / dream-resumed / dream-redirected / investment / qualification / employment / fate-result` 是拟新增语义。动作发生时的年龄/槽来自宿主fact，不信任用户输入。新事实引用用(branch,slot,eventId,choiceId,actionId)，旧引用仍合法，不改写老事实。

禁止给run另建可独立写入的“dreamProgress”。`continuity.dreams(run)`、`candidates(run)`、`qualifications(run)`与工作安排查询均由facts和正式配置派生；可缓存但必须可清除重建。来源事实中的branch可能属于分叉前父人生，保留原ref，不为子分支篡改共同历史。

## 3. 可编码接口与行为

|位置/拟接口|输入/输出|强制约束|
|---|---|---|
|C目标声明|routeId/kind/goal/discovery predicates/合法窗口/资格/动作/结果规则版本|仅声明可用内容，不自动产生事实；01等不复用admit/rank等生活wish ID|
|L.candidates(run)|由真实接触事实返回[{routeId,sourceRefs,target,legalWindows,unavailableReason}]|无接触为空；成年来源同权；候选不是已确立；不可达荣誉说明限制，允许明确的领域转向|
|L.dreams(run)|按routeId返回首次确立来源/年龄、状态、投入refs、成果refs、暂停/重拾历史|确立B不暂停A；失业/换job不清梦；候选不入“曾确立”回忆录|
|E.chooseDream(run,id,operation)|仅event未提交时写draft中的意向；operation为establish/pause/resume/redirect/cancel|重新校验候选/既有状态；重复确立安全no-op且不覆盖首次年龄；cancel撤回草稿|
|E.preview(run)扩展|返回合法动作、资源预算、冲突项、资格不足、可延期到哪槽|纯查询不发钱、不记投入/就业/荣誉；视口不进入结果随机数|
|E.canApply / commit扩展|统一验证main+dayExtra+followup+新增活动/目标操作|先全量预检，再一次应用。失败不留半个资格、费用、工资或historyKey变化；同槽重复commit仍false|
|L.evidence/growth扩展|按专业、动作、成果、时间段筛选来源|同动作多route只计一次收益；至少两不同槽是重复投入下限，不等于自动达最高目标|
|窗口适配|C窗口声明+schedule/currentCard/followups合法承接|不能只扩opportunityWindow就假设card会跨槽出现；续接必须有当前真实scene/action，追原window/source，重检当前资格|
|工作安排适配|从employment收据派生主职/兼职/短班/离岗/失业|现有career作为主要身份兼容显示；新岗位薪资策略只结一次；梦想目标与就业互不替代|
|规则检验适配|resolveFate(context)→资格失败/落选/成功/主动退出等结果与来源|不直接写状态；只有commit收录结果。返回规则版本、attempt、准备refs、外因及费用|

候选的发现与确立可以在同一场景分步发生，但不能引用尚未合法提交的虚构事实。若本场接触与确立一起确认，先用经过重演的动作收据建立本槽事实，再以本槽动作ref关联确立，整体一次提交；不得依赖“刚渲染过”作来源。首次实现可采取下一槽显露已有事实，减少同槽引用复杂度。

## 4. 资源与时间（新活动版本，不能改旧结算）

新路线活动在每槽声明两段可支配日程 `timeCapacity=2`：常规新主事占1段，轻活动占1段，重训练/考试/拍摄/旅行段占2段；短回响仍至多1项并与新轻活动共用剩余段，不另获免费第三段。已有dayExtra同样占这个剩余段。家庭必需动作若已由主事承担不再计两次；否则占段并展示冲突。选择确认/暂停本身可0段，不能包含隐形投入。

已有dayPlan的主成本为2时仍算2，不能为了塞入梦想改成1；未适配的纯旧主事/extra/followup组合保留原P2行为，只有选入新活动时才按新合同合并预算，避免倒改旧存档或删去旧合法操作。容量表中18个余段是新活动模型的上界，必须扣除已有占满日程和回响。

精力仍沿用E.energy：新动作显式声明energyCost；主事维持旧hotspot主费用。新窗口适配器必须完整核算其场景的精力；旧未适配卡保留原费用，不回溯扣费。支持项、短回响、新活动统一预检remaining，不能一项系统扣完另一项仍可免费选。

这两段是叙事时期内有意义的生活安排，不是每槽两天，更不是两段就完成五年医学课程。跨年连续课程/训练必须有玩家明确选择的期间安排与持续投入收据；检查真实age差、学制、休学/就业中断；不补造中间比赛/手术/学位。每槽最多一项主专业操作+一项短行动，避免增加弹窗税。

新活动收费声明整数个人money、健康/压力代价、受影响工资；个人余额不足时不得做无担保支出（现有合法债务保留，允许另有明确贷款来源的内容）。家庭budget与儿童专款不得混扣。初始建议成本：轻练/复习50–150、器材/交通按具体场景，正式金额在路线制作中平衡；免费公共接触只耗时间，保证低资源有入口。重活动占工作责任时明确请假/少班/调岗或离岗及其收入影响，不强制所有梦想先辞职。

工资：旧卡/旧档继续旧+300路径；新employment payPolicy参与的槽排除那份旧通用工资，收入按同一paySourceId去重。兼职必须来自真实第二聘约且不超时间；学生/离职/失业不能凭过去careerLog领工资。P3-1实现策略与反例，不在本阶段臆造八类完整薪资表。

## 5. 命运检验协议

保留旧检验以保持旧种子兼容，新路线使用显式版本，不能改变旧historyKey决策序列。新协议：

1. 资格硬门：真实学历/训练/许可/报名窗口/作品；不足不执行成功抽样，解释缺项。
2. 准备证据：多槽、不同类型、真实耗费，不靠单属性；记录参与者、来源及有效期。
3. 实际参与选择：接受机会≠参加≠胜利；退出/不参加不授成绩。
4. 外因有界：新规则可用 `hash(seed, ruleVersion, routeId, opportunityId, attemptId, opportunitySourceKey)`，opportunitySourceKey固定为该考次真实机会来源；准备摘要作为收据与质量输入单列，不因多练一次改变外因桶，以便同种子更多准备的对照有意义。避免视口/时间戳/导航/无关草稿影响。参与同一考次只允许一条结果；改变准备只能在未结算前经真实投入，不靠反复点击改随机。
5. 结果收据含资格结论、准备refs、外因桶、outcome、已付成本与合法后续。生产UI讲具体阻力与反馈，不显示成功概率刷点。

参考测试规则（仅夹具）：至少3次不同槽投入且含技术/实践两种类型才合格；质量0–70+选择0–20+外因[-5,5]，门槛80。它用于验证增加真实准备改变边界结果、属性再高无资格也拒绝、外因不能拯救完全不准备；不是十八路线共用成功公式。奥运、招生、聘任、作品评审分别制定真实规则。

`attemptId` 来源为真实届次/考试/比赛/项目提交窗口，刷新、改草稿顺序和再次导入不得增加；下一次考试必须有新的合法窗口、准备和费用，不能沿旧attempt无限重试。无“每一生必有一次传奇”配额。

## 6. 机会与冲突

保留P2关键主事件、旧菜单、原胜出默认与45→46试玩续接。新活动通过声明适配后纳入菜单/短动作，不能全局改变注册优先级导致旧风险/提前谢幕消失。硬截止赛事/当日两处赴约只能自主取舍；文档声明的替代日可延期，资格失效要invalidated。未曝光候选关闭仍seen=false，不能强写declined。

新核心机会必须给出fallbackSlots或“真实无后窗”的解释、当期看得见的冲突及失去后的普通生活。14/18岁考试和39/35岁决赛不得延期几年冒充同届；45→46八年跨度只限旧文件这种可保存对象，不当见面补偿模板。
