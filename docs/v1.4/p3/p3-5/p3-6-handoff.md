# P3-6 可复跑验收合同

1. 从项目根目录执行本目录 tests-and-browser.md 的 Node 和 Chrome 命令。保留每个进程退出码。运行本目录 export.cjs 重建矩阵、逐槽覆盖、同前缀对照及多梦想见证。
2. 逐路线读取 P3-2 的 branch-witnesses.md、P3-3 的 branch-witnesses.md 和 P3-4 的 branch-witnesses.md。按见证中的人生名、种子、职业、时点、站点方法重跑直路、弯路、未竟或无梦普通线。十梦编号为 01、02、03、07、08、11、12、25、29、30；八职为 J01—J08。检查取得资格、未取得资格、暂停、重拾、离岗及再聘时的实际收据。
3. 对照 intersection-matrix.generated.md 的 80 格；再从 causal-evidence.generated.json 用 X01A 至 X13C 抽取分叉前事实、分叉菜单、工资、活动费用、后来操作、人物物件和终章。13 组的前缀必须深相等。暂停清北期间应仍可投开源，回到清北时仍应使用原来的成立记录。
4. 验证 60 个出生入口分别从种子 1、2、3、4、9、12 的新人生接触并确立，另核对 80 个在职样本。年度报名、训练、正式赛届、医教资格、票证、体力、房租及经营周转金分别构造可行与不可行条件。超预算必须在单次提交前失败。
5. 检查八种无梦普通人生的第 30—40 槽，以及 38、45、64、72 岁的实际日期。对照普通人生的逐槽菜单与实际工作，验证晚年回响能找到操作来源。种子 2 的「较早的一页」应在 44 槽结束，未到的年份不能出现在回忆录。
6. 重跑食堂现金不足、预付退款、亏损、尾薪、转让、二次开业、再受雇、跨岗前清算反例。确认每次服务或清算只有一笔款项，每一份耗用库存只出库一次。重跑 425、474、465 的 P2 调度，验证草稿、继续、导入、父子分支及命运检验。
7. 本轮新增 0 个主事件、0 个主选项、14 个路线工作台动作及 18 个方法选项。食堂占 9 个动作、10 个方法；办公室、制造、配送合计 5 个动作、8 个方法。另增「这次明确谢绝」手记控件。读取 actionId、payload.method 与 result 前先区分实际提交和只在菜单出现。
8. P4 评审移动阅读、焦点和动效；P5 安排初见玩家和实体手机验证趣味、时长以及第一次理解预算的行为。P3-6 仍需扩充来自真实历史版本的未修改备份，并抽查长时间间隔中人物、住处与物件归属。
