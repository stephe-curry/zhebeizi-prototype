# 《这辈子》v1.4 P0 工程审计

2026-11-19。审计对象是 prototype/v1.3 的工作树，包括 HEAD 之后的器材室改动。产品依据是相邻 v1.4 目录中的两份三项修订版，历史文档在 ../../这辈子_游戏产品文档_v1.3.1.md。未在 game 目录找到独立 T5.2 因果台账原件。当前任务书授权到 P0 为止。

## 能力边界

当前是真实可完成的一生。槽位、选择结算、职业替换、旧物去向、低谷恢复、分支与回忆录已有可执行规则。六岁至十三岁的消费和保留都能开放不同的参与机会。普遍欠缺的是机会的递延／失效历史、成长证据汇总和 S 类各结局的可靠再遇。完整原型需要 L1 和 L2 都达标，L3 逐项诚实标记。30–50 分钟与当下趣味尚无本轮真人数据。

## 代码调用与数据

1. index.html:9 起按序载入内容、动作、引导、存档、引擎、图集、动画、声音和专用场景，最后 app.js。首页 setup→birth→E.create(seed,{childhood:'spring-gift',…})→start 建树或分支→persist→render。正式入口与 tests/childhood、tests/guidance.html 独立。
2. engine.js:93 origin 对六种身份等概率取样，再在 create:153 叠加基础状态、自由点和天赋。学霸增加知识12、期待14、压力5；孩子王社交12、人脉5、知识−4；运动苗子体能13、健康5、知识−4；富二代家庭预算28000、期待10；手艺家庭技能12、预算−4000；外婆带大心态10、心情4、家庭−8。预算是家庭字段。手艺家庭会改变旧灯与雨天木桥，外婆改变照护者和对白，运动苗子有雨天扶人变体。其他身份主要通过初值、门槛与文本影响人生，尚无六套专属内容。
3. prepare→schedule:121 选基础卡，currentCard:16 再按出生、已提交事实、人物、物件和草稿版本改出实际选项。age 表以 slot−1 索引。1–4童年、5–22求学、23–40职场、41–46后半生；严重病情可以在44结束。
4. app.play/mutate → 普通日程、工作台或 LifeShop/LifeDinner/LifeGift。T1 的 create/update 只记录草稿输入，replay 对照当前对象、余额和前置条件重演，preview 给出可行动作与 ready。普通选择经 E.preview/canApply；统一 E.commit:526 检查回合状态、已结算、资源和行动资格，应用命令并写 fact，置 committed、stage=result。下一回合由 advance 创建新草稿。旧流程也可直接到同一提交边界；单次提交保护不等于任意故障下数据库级事务。
5. guidance.js clock.sample 对阶段、观察、动作和可用列表的变化重新计时；describe 根据合法动作生成目标、推荐与帮助，默认8/18秒，完成停止。app.updateGuide 对可见性、弹窗、活动做暂停判断。大部分老卡没有该协议。
6. content.js 保存定义。run.stats 保存六维、健康、一般金钱、家庭预算等，精力由 body 推导；run.people 保存联系状态，run.items 保存 first/state/trail，run.experience 保存经历首次来源槽，careerLog/wishLog 保存职业心愿变化。run.facts 保存每次正式选择、文字、来源槽、机会、关系、物件、回响。draft、result、聚合状态各有职责；常规事实没有完整经济差分，当前 result.deltas 不能充当永久逐回合账本。
7. engine.hash(seed,historyKey,…) 决定机会、录取、事故等；提交选择和安排推进 historyKey。八岁看价等过程不改变后续抽样。scenes.js 从 sprite-data.js 取帧、处理减少动画；style.css 控制竖屏命中与布局；audio.js 用 Web Audio 合成提示。图像／声音是表现层，不能用它们反推已完成的事实。
8. app.edit/persist 用 revision、可用时的 navigator.locks 和 storage 事件协调写入。save.js decode 恢复已知格式及旧草稿，validateImport 验证导入。memoir:644 从事实选时间线和与叙述者真实交集；fork:691 恢复选定检查点，claimEnding:767 按树防重复奖励。回忆录是选择性投影，某条 fact 被写入不等于文本中一定可见。

## 核心机制对照

|目标|已有证据|缺口|
|---|---|---|
|Fact|一次结算、来源槽、部分来源动作／收据|人物相遇与首次来源不代表当时尚在场；展示还有按动作中文匹配的读取|
|Opportunity|第33槽三邀约及35槽后果；第6槽 taken/passed|欠缺统一的 eligible/offered/accepted/resolved/declined/expired/invalidated，覆盖候选没有生命周期|
|LifeThread|school/esport/indie 累积 steps，暂停，项目关闭、职业转行|三条线采用不同条件，esport 的规则不看 paused；未提供四条 L2 梦想的五阶段对应|
|Evidence|真实经历和来源、资格部分看多次投入|direction 命令直接赋值，换岗也直接赋方向；没有按事实去重、时距与领域区分的资格|
|Echo|物件 callbacks、人物 relationshipEcho、八岁到十三岁可执行新动作|多数是结算文字；事件出现、玩家实际看见、实际行动三者未普遍区分|
|存档、终章|版本、独立 key、分支、提前/开放/自然谢幕、一次自由点|旧档缺字段时不能从职业或文案倒推历史；旧结局引语仍挂在电竞冠军|

## 风险与顺序

- **阻塞 L1**：engine.schedule 单槽胜者独占。480 个 seed 中 425 在第39槽选中电竞决赛并覆盖已符合资格的独立游戏发布，474 在第45槽出现三方竞争。重要机会没有下一窗口或合法终止收据。P1 建机制，P2 配窗口。
- **高**：第29槽旧友笔记只验联系和随机数；档案里错题本提示只验升学线。第19槽旧文件只验创作线，不能证明曾和同一个人制作同一个作品。P1 建可追溯条件，P2 修实际前情。
- **高**：健康风险已有真实经济成本，但恢复卡只在第38/41槽读 active；错过后的替代与合法终止需要逐窗证明。第40槽岗位与休息的差别未普遍变成晚年行动。P2。
- **高**：三项修订明确四梦三职；奥运、两类创业、主动安家缺少达成／未竟链。电竞寄语需按新版本挂到奥运并兼容旧终章。P3。
- **中**：存档对局部来源的验证强弱不一，旧台灯结果图和回调依赖文字。P1 固化旧档样本，避免重新解释已提交记录。
- **低**：一般房间的物件文字热点和通用场景动作与专用像素场景体验不齐。P4 优先 S 节点。是否好玩及整局时长由 P5 真人集中验证。

## 验收口径与剩余缺口

101 张由 46 公共、20 职业、33 条件、2 新童年卡组成，基础注册选择 306 个。人工建议 S 15、A 71、B 15；等级是后续制作责任，不能作为已兑现率。12槽可限时刷题，29槽可启动旧桌面活动；同窗卡本身的选择以外仍可有共享活动。101 张在现有测试（含夹具）有成功提交；正式卡测试留样417条。独立480条自然调度样本走到96张，475条到46槽，5条提前谢幕。在 observed-links.generated.md 按同一人生的来源事实列出606对实际选择引用。间接属性读取、纯叙述、屏幕曝光和可玩回响不能互相替代。S 各选择的跨年实质兑现率和 A 可信后读率目前没有完整运行时度量，不能据以上数字宣布达标。

第38槽恢复已高于普通条件卡，提前谢幕与决赛优先于恢复，但它们目前不在同一槽；不能据全局优先级声称已有“决赛覆盖恢复”的实际案例。未在自然样本命中的5张中，life-24/27/32 恰好都是四种初职的岗位覆写槽，life-36 被风险或职业故事占用；late-recovery 需要到41槽仍处 active。P2 应对每张补合法前缀或标注不可达的充分依据，不能为覆盖率把 eventId 硬塞进 run。
