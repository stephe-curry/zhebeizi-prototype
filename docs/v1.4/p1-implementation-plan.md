# P1 最小兼容改造提案

1. **锁定数据合同**。留存旧 life-1/2、旧/新饭桌、两个版本悠悠球、器材室 taken/passed/未呈现、已结束旧人生及分支的隔离存档夹具。以 seed、来源槽、eventId、choiceId 和已发生动作核对新旧加载，保存完整原快照。维护旧哈希输入，导航和求助不能改变未来抽样。
2. **在唯一结算边界标识来源**。engine.commit 依旧是长期状态入口。为新事实添加可序列化的事件变体、来源引用和必要的道具、持有者、钱款变化。用分支＋回合定位事实，分叉保留祖先引用；历史槽号不能跨树直接拼接。旧档默认未知，不把缺字段解释为否认／已错过。将自动来源判定从显示中文逐步改为可信谓词。save.decode/validateImport 做增量兼容，不能改写旧事实。
3. **声明候选与窗口**。content 声明条件、窗口、优先级、合法替代与终止原因。engine.prepare/schedule 输出本槽候选、胜出者和可延期项。先影子运行，逐种子对照 v1.3，P1 不全面改选卡。必需窗口被覆盖时记录待处理；年龄、人物离世、旧物丢失分别判断真实失效。
4. **区分呈现和参与**。app.play 完成实际展现后以稳定机会 ID 幂等记录呈现状态；避免整页重绘重复计数。接受、完成和放弃依托动作与 E.commit；渲染不能发放奖励。必须区分“出现过但选择别项”“资格失效”“同窗被覆盖”“玩家从未看见”。刷新后继续当前合法状态。
5. **从事实派生证据与线史**。集成现有 threads、experience、people 与 careerLog。去重同一来源；实际练习、认得旧物、购买分别建模。回响的承诺窗口、看见、参与和结果引用独立；UI/回忆录只消费可追溯投影。不得增加第二套奖励或长期事实权威。
6. **第一批自动验证**。真假修灯和独自做错题、朋友未共同写笔记、无成品的项目回访；三种存钱×买留×器材室参加或不参加；拒绝、过期、未呈现各自恢复；并窗决赛／发布、恢复／转型、早终／晚期旧物；重复点击和跨分支恢复；相同种子相同选择的46槽轨迹、树奖励一次。校验生成台账与注册／实际提交一致；要求真实 run 证据，不以直设 eventId 测资格。
7. **交接界限**。P2 才为每一 S/A 卡配置足够的后续读取与窗口，B 卡验证当下动作；P3 对四梦三职分别录制继续和未竟／转向人生；P4 完善场景；P5 统一人工试玩。机器回归搭桥，不替代 L2 可玩性评审。
